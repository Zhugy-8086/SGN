# MSint×Level 画廊演示设计：一份数据，所有画质（demo_gallery）

> **定位**：放弃游戏方案（v3 否决），改用**像素画廊**——工具型展示。
> 为什么换成画廊：图片视角的展示性不比游戏差，甚至更强——一份数据同时是
> 高清/标清/马赛克，切换零延迟零加载零副本，这个反差在图片上最直观、最惊艳，
> 且制作成本远低于游戏。
> **本文件中心**：MSint×Level 特性全集（§1）→ 与"外部压缩+多分辨率"的
> 新增效果差异（§2，差异化依据）→ 两章画廊叙事 + 硬隔离 UI（§3，执行方案）→
> 伪代码结构与 UI 布局（§4）。
> **本文档不包含代码实现**，是设计原稿；实现另起 `demo_gallery.py`。

## 2. 新增效果差异：MSint 多视图 vs 外部压缩+多分辨率

> 回答"一份数据存所有压缩数据，算不算新增效果"：**算，但不新增在压缩率上**。
> PNG/gzip 的压缩率可能更高；MSint 的新增效果在**视图是计算数据类型、
> 切换零成本、单拷贝一致性**三个维度——这三条是任何存储格式都没有的。

| 对比维度 | 外部压缩（PNG/gzip）+ 多分辨率 | MSint 一份母本多视图 | MSint 新增效果 |
|---|---|---|---|
| 多分辨率 | 多份文件 / 加载后重缩放（新副本） | 掩码/位操作切换 | ✅ 零新副本、纳秒级 |
| 文件能否直接计算 | 否——必须解码成像素 | 视图**本身就是计算数据类型**（int4/int8 直接进 SIMD/ALU） | ✅ 无需解码即可参与计算 |
| 画质一致性 | 多文件自己维护同步 | 单拷贝：一个母本权威，数学保证一致 | ✅ 改一格全联动 |
| 本质 | 存储格式（熵编码） | 计算范式（同一数据多精度语义） | ✅ 不同维度 |
| 压缩率 | 可能更优 | 按位宽线性缩放（4bit = ¼） | ➖ 不作卖点 |

**宣传定位**：差异化绝不打"压缩率"，打 **"同一个文件，同时是高清/标清/马赛克，
切换零延迟零加载零副本，且每个视图都是能直接算的数据"**。

## 3. 执行方案：两章叙事 + 硬隔离 UI

> 原则：**先内后外、先快后慢**。第一章讲"内存里的速度"，第二章讲"磁盘上的闭环"。
> 三条铁律：UI 硬隔离、动作分离、术语标注严谨。

### 3.1 演示流程（总时长 90~120 秒）

| 章节 | 名称 | 核心交互 | 展示内容 | 对应特性 | UI 布局侧重点 |
|---|---|---|---|---|---|
| **第一章** | 运行时：解读即速度 | 拖拽滑块（16→1bit） | 画面风格连续突变；粒子模拟吞吐实时跃升（如 6M/s→90M/s） | T1/T2/T3/T9 | 画面中央 90% 沉浸，左上角仅位宽+吞吐 |
| **第二章** | 持久化：存储即投影 | 导出存档→选位宽→加载复原 | 柱状图（16bit:2KB, 8bit:1KB, 4bit:0.5KB）；加载后**投影一致性校验**通过 | T4/T10 | 主画面 60%，右侧 40% 独立面板，标"持久化层（磁盘 I/O）" |

### 3.2 硬隔离措施

1. **标题区隔**：第一章顶部固定 `[ 内存操作 ]`（绿），第二章侧栏顶部 `[ 磁盘存储 ]`（蓝）。
   颜色+文字双编码，杜绝"加载延迟"归咎于"视图切换"。
2. **状态栏注解**：每个存档文件旁标注
   - `16bit 导出: 指向母本区段 [0:1024]`
   - `4bit 导出: 指向母本区段 [0:1024]（共享物理存储）`
   - 底部汇总：`物理存储实体计数：1 份（无副本）`
3. **动作分离**：拖拽滑块只改内存视图（微秒级，无进度条）；点按存档按钮才触发
   磁盘读写（毫秒级，带进度条）。感官上明确区分两者的物理性质。

### 3.3 关键修正（相对早期版本，必须执行）

1. **投影一致性（不是"复原母本"）**：4bit 视图是降维投影（int16→16 级，信息丢失）。
   "加载复原"的正确语义 = **投影一致性校验**：16bit 导出文件在 `view(4)` 下与
   4bit 导出文件**逐位完全一致**——两个不同大小的文件，在公共视图层是同一份数据。
   加载 4bit 存档 = 把母本量化到 4bit 精度（部署降精度语义，feature 不是 bug）。
2. **性能指标用"粒子模拟吞吐"**（每秒更新粒子数，numpy 位运算实测），
   **不用渲染帧率**——matplotlib 渲染是瓶颈，帧率数字会被渲染主导，看不出位宽差异。
3. **对照 PNG 的红线**：只比无损（PNG/gzip）压缩率，禁与 JPEG 对比（有损不可逆，
   会暗示视图切换有损）；PNG 条旁永久注释——"PNG 基于熵编码，针对磁盘存储优化；
   MSint 位宽导出针对内存计算与 I/O 一体化优化，导出后无需解码即可参与计算"。

## 4. 伪代码结构与 UI 布局

```
demo_gallery.py
├─ 数据源：sgn.MultiScaleView 母本（int16[1024]，内置 DEMO 渐变图 + PI 噪声图）
├─ 第一章（内存层，绿标）
│   ├─ 中央画面：当前视图渲染（matplotlib imshow / blit）
│   ├─ 滑块：位宽 16→1（onchange → 仅换掩码，不重建数组）
│   ├─ 粒子风暴：numpy 位运算模拟，右上角显示吞吐（粒子/s）
│   └─ 左上角：位宽 + 吞吐数字（唯一 HUD）
├─ 第二章（磁盘层，蓝标，独立侧栏）
│   ├─ 导出按钮 + 位宽下拉 → 生成 .raw（紧密打包）
│   ├─ 柱状图：各位宽导出体积（16bit:2KB / 8bit:1KB / 4bit:0.5KB / 2bit:0.25KB / 1bit:0.125KB）
│   ├─ 加载复原按钮 → 进度条 → 投影一致性校验（逐位比对公共视图）
│   └─ 状态栏：区段标注 + "物理存储实体计数：1 份（无副本）"
└─ 模式切换：Tab 键切章（绿色↔蓝色，画面从全屏沉浸缩至 60%）
```

UI 布局（1280×800 基准）：
- 第一章：画面 0,0 → 1280,800 全屏；左上角 HUD 80×40
- 第二章：画面缩至 0,0 → 768,800；右侧面板 768,0 → 1280,800
  （标题栏 40px 高，柱状图区 240px，存档列表区 200px，状态栏 60px）

## 5. 技术选型

- matplotlib 交互（slider + button + key_press，FuncAnimation 循环），零新依赖，RDP 可跑
- 依赖：sgn.MultiScaleView + numpy + matplotlib（全部已有）
- 产物：`demo_gallery.py`（弹窗可玩）+ `--save gif`（自动走 §3.1 流程录片）
- 存档：按位宽紧密打包（.raw），无外部压缩库依赖；投影一致性校验 = numpy 逐位比对

## 6. 历史否决记录（防止重蹈）

- **v2/v3 游戏方案**（"一个世界八种活法"）：否决。理由——游戏载体炫目但制作成本高、
  特性映射牵强（T14/T15/T16 无游戏落点需硬塞）；画廊方案聚焦"同一份数据所有画质"
  这一个核心反差，制作快、效果更强、特性集中。
- **早期"800 字节最小游戏"**：否决。理由——"数据小"撞极小游戏圈既有记录
  （Kkrieger 96KB FPS、Steam <512KB、Atari 2600 4KB），维度混淆且非 MSint 独有。
- **早期"展示字节数小"**：否决。理由——压缩率 PNG 可能更优，非差异化点。
