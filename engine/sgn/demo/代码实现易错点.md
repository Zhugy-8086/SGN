# demo_gallery 代码实现易错点清单

> **本文件中心**：实现 `demo_gallery.py` 及其模块时，已踩过/高概率踩的坑，
> 每条 = 坑 + 后果 + 正确做法。开工前通读，实现后对照检查。
> 依据：本项目已有事故记录（银行家舍入、中文字体豆腐块、日志污染 stdout 等）+ 平台特性（Windows/RDP/matplotlib）。

## 1. 视图语义类（MultiScaleView 核心）

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| V1 | 视图切换时复制数组（`arr.copy()`） | "零成本切换"变"有成本"，第一章速度反差崩 | 视图 = 母本引用 + 掩码/位操作，**不产生新副本** |
| V2 | 用纯截断提取视图 | 每步 ~50% bin 不一致，操作界崩（T2 红线） | 必须 round 语义：`np.round(q / 2^(16-bits))` 后回放 |
| V3 | 用 `np.round` 以为是对称舍入 | **np.round 是银行家舍入**（.5 舍到偶数），与 C round 不一致 | 需要对称舍入时自实现（`floor(x+0.5)`）；或明确文档说明使用银行家舍入且长期无偏 |
| V4 | 负 int16 的移位/掩码 | 符号位污染提取结果 | 先取无符号视图：`q.astype(np.uint16)` 再移位 |
| V5 | 取高 4 位还是低 4 位没定义清楚 | 导出/校验对不上 | 全项目统一：**视图 = 高 bits 位（值域方向），导出 = 同一定义**，文档写明 |
| V6 | 非 2 的幂位宽硬用（如 5bit） | 4↔5bit 陡崖，表现非线性，观众困惑 | 滑块只给 1/2/4/8/16 档位；分数位宽不进 UI（T18） |

## 2. 导出/加载语义类（第二章，最容易错）

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| E1 | 宣称"加载后复原为同一份母本" | **数学不成立**（4bit 是降维投影，信息丢失），宣传翻车 | 话术用**投影一致性**：16bit 导出在 view(4) 下与 4bit 导出逐位一致 |
| E2 | 投影校验比对"还原母本" | 永远失败（4bit 装不下 16bit 信息） | 比对公共视图层：`view(f16_arr, 4) == f4_arr` 逐位 |
| E3 | 紧密打包字节序/对齐错 | 跨机器不一致、校验失败 | 固定 little-endian + 明确每值占位；`np.packbits` 或自实现并单元测试 |
| E4 | 加载写回母本时覆盖全部区段 | 误以为是 bug | 语义定义为"量化写回"（母本降精度 = 部署降精度 feature），UI 文案注明 |
| E5 | 文件大小公式 `母本 × bits/16` 忘记整除 | 边界（1bit 时 1024 值 = 128 字节）算错 | 统一走一个 `export_size(n, bits)` 函数，单测覆盖 1/2/4/8/16 |

## 3. 性能指标类（第一章反差核心）

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| P1 | FPS 用渲染帧率 | **matplotlib 渲染是瓶颈**，位宽切换看不出差别，速度反差崩 | 指标用**粒子模拟吞吐**（每秒更新粒子数，numpy 位运算实测）；渲染帧率单独显示或隐藏 |
| P2 | 粒子模拟用 Python 循环 | 几万粒子卡死 | 全程 numpy 向量化（数组运算），4bit 用 uint4 打包模拟 |
| P3 | 滑块回调里重建 imshow/figure | 每拖一次重建，卡顿+闪烁 | 回调只 `set_data` + blit；figure/axes 只建一次 |
| P4 | FuncAnimation 与 slider 共用重复绘制 | 双循环冲突，画面撕裂 | 单一更新源：要么滑块驱动，要么动画轮询；明确二选一 |

## 4. matplotlib / Windows 环境类

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| M1 | 中文字体不设 | 豆腐块（本项目已踩过） | 全局 `plt.rcParams['font.sans-serif']=['Microsoft YaHei']` + `axes.unicode_minus=False` |
| M2 | RDP 下默认后端黑屏/无窗口 | 弹窗看不到 | 显式选后端（TkAgg），`matplotlib.use('TkAgg')` 在 import pyplot 前 |
| M3 | 窗口关闭后动画线程残留 | 进程不退出 | 绑定 close event 停止动画；`--save` 模式不建窗口 |
| M4 | 路径硬编码 `\` 或 `C:\...` | 换机器崩 | `os.path.join(os.path.dirname(__file__), ...)` 相对定位；输入输出全走此路径 |

## 5. 工程/流程类

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| S1 | 日志混进 stdout | 录屏/输出被日志污染（本项目已踩过，logs/ 目录成因） | 运行日志重定向到 `demo/logs/`；stdout 只留程序交互输出 |
| S2 | 随机性不可复现 | 演示两次不一致 | 母本生成固定 seed；粒子/效果若随机则同 seed |
| S3 | `--save` 模式走交互流程 | 录片卡在等按键 | `--save` 自动执行演示路径（定时触发各动作），不弹窗 |
| S4 | 新依赖 | 环境不一致跑不起来 | 只用 numpy + matplotlib + 标准库（PIL 仅在 --save 用） |
| S5 | 主程序一个文件塞全部逻辑 | 难调试难复用 | 按文件设计.md：gallery_data（数据）/ gallery_export（磁盘）/ demo_gallery（UI）三分 |

## 6. 宣传红线（代码/文案层必须守住）

| # | 红线 | 正确实现 |
|---|---|---|
| R1 | 不打"压缩率"卖点 | UI 文案禁"压缩""更小"为主角；差异化文案 = "同一份数据，所有画质，零延迟切换，视图可直接计算" |
| R2 | 禁与 JPEG 对比 | 对比参照只用 PNG/gzip（无损）；JPEG 一律不出现 |
| R3 | 动作分离 | 滑块只触发内存视图切换（微秒级，无进度条）；存档按钮才触发磁盘 IO（毫秒级，有进度条） |
| R4 | 加载语义不误导 | 加载低 bit 存档 = "母本量化到该位宽"，UI 明示，不写"无损还原" |
