## 1. 背景

SGN SIMD 原语层（`engine/sgn/simd/`）含 AVX-512 服务器加速内核（P1，见
[simd服务器加速计划_2026_08_30.md](../engine/sgn/fixes_相关修复/simd服务器加速计划_2026_08_30.md)）。
本机（Arrow Lake，无 AVX-512）无法真跑 AVX-512 指令，只能逻辑验证算法。
本测试在远程云主机（EPYC Zen 4，全核统一支持 AVX-512）上对 `simd/` 目录
做独立验证：**正确性 238 项 + 性能基准**。

## 2. 测试环境

| 项目 | 详情 |
|---|---|
| CPU | AMD EPYC 9Y24 96-Core（Zen 4, family 25 model 17），KVM 完全虚拟化 |
| 分配 vCPU | 2 核（2 socket × 1 core，无超线程） |
| 频率 | 2596 MHz（约 2.6 GHz） |
| 内存 | 4 GB（虚拟机；底层 EPYC DDR5） |
| OS | Ubuntu 22.04 LTS，内核 6.6.95 |
| 编译器 | g++ 11.4.0 |
| 编译选项 | `-O3 -std=c++23 -mavx2 -mavxvnni -mavx512f -mavx512bw -mavx512vl -mavx512vnni` |
| 运行时后端 | **`avx512vnni`**（CPUID 运行时自动检测选中） |

CPU 关键指令集：AVX2, AVX-512F/DQ/CD/BW/VL/IFMA/VBMI/VBMI2/**VNNI**/BITALG/
VPOPCNTDQ/BF16, GFNI, VAES, VPCLMULQDQ, SHA-NI, BMI1/2。

> 注：Zen 4 的 256 位 AVX-VNNI（VEX）在 /proc/cpuinfo 未列出但 CPUID leaf7 sub0
> ECX[4]=1；运行时优先选中 AVX512-VNNI（EVEX），不触发 256 位 VNNI 路径。

## 3. 测试方法

### 3.1 正确性（238 项）

每个原语与标量锚点逐位/容差对比（`sgn_benchmark.cpp` 内嵌 ref_* 参考实现）：

| 原语 | 项数 | 测试要点 |
|---|---|---|
| dot16 | 18 | K∈{0,1,7,8,15,16,17,31,32,33,63,64,65,127,128,1000,65536} + 全 INT16_MIN 极值；位 exact |
| dot8/dot4 | 28 | K∈{0,1,7,8,31,32,33,63,64,65,127,128,1000,65536}，含 255×127 满幅；位 exact |
| sum_f32 系 | 108 | n×stride 组合，kRounding 档相对容差 1e-4（SIMD 分块 vs 标量顺序舍入差异属预期） |
| decode_i16_f32 | 10 | n∈{0,1,3,7,8,9,15,16,100,1000}，含 0x8000/0xFFFF；位 exact |
| reverse/batch | 64 | n=1..8 单值 + nv×ns 批量；位 exact |
| accum_f32 | 10 | n∈{0,1,7,8,9,15,16,17,100,1000}；位 exact |

### 3.2 性能（K=1024/4096/16384/65536）

- 时钟：`clock_gettime(CLOCK_MONOTONIC)`
- 预热 50 次，多次迭代取均值（iterations: 小 K 5000-8000，大 K 2000-3000）
- `volatile sink` 防止死代码消除
- 度量：us/call + Mops/s（Mops = 百万元素/秒）

## 5. 分析

### 5.1 对项目验证的意义（本机做不到的三件事）

1. **AVX-512 真指令路径 bit-exact 确认** —— 512 位 madd（dot16，含最近实现的
   `_mm512_madd_epi16` 快速路径）与 512 位 VNNI（dot8/4 `_mm512_dpbusd_epi32`）
   在真 EPYC 上数值正确。此前只能逻辑测试（madd512_logic_test.cpp），现真指令补全。
2. **AVX512-VNNI CPUID 修复生效确认** —— 后端名 `avx512vnni` 证明 leaf7 sub0
   ECX[11] 检测正确。若仍误读 sub1（恒 0）则后端名会是 `avx512f`，512 位 VNNI
   路径永不启用（见 全局AVX编译参数移除调查 审查发现 2）。
3. **dot8 > dot16 符合理论预期** —— 512 位 VNNI（64 MAC/指令）吞吐是 512 位
   madd（32 元素）的约 2.5 倍（57.6 vs 23.1 Mops/s），验证内核选型正确。

### 5.2 备注

- 测试用**一次性全局全开编译**（所有源文件带全部 ISA 选项），非 build_remote.sh
  的 per-file 方案。不影响验证有效性——阶段 1 已去宏短路，dispatch 全走 CPUID，
  `avx512vnni` 是 CPUID 真结果（非编译期宏假象）。
- per-file 方案的编译链路已在本机验证（链接 + 边界测试 ALL PASSED），
  后续可在 EPYC 上用 `build_remote.sh` 复验 + 强制后端对比。
- 虚拟机 2 vCPU + 4GB 内存，性能数据为单核基准（无多核并行，dot 原语本身单线程）。

## 6. 结论与后续

- **结论**：simd 原语层在真 AVX-512 硬件上正确性全过、性能符合设计预期；
  AVX-512 内核（P1）与 madd 快速路径（dot16 512 位）验收通过。
- **后续可选**：
  1. EPYC 上用 `build_remote.sh` 复验 per-file 方案 + `SGN_KERNEL_BACKEND` 强制后端对比
  2. 多核 OpenMP（P2，需在 narrow_dot 层并行，见 simd服务器加速计划 §9）
  3. 对齐/预取（P2）、BF16/GFNI（P3）留待后续
