## 0. 本归档要点（兼容能力）

作为"兼容能力"证据链的 Zen 4 拼图（对照表见 Zen 5 归档 §0）：**同一套源码**在
Intel（256 位 VNNI）/ AMD Zen 4（512 位 VNNI）/ AMD Zen 5（512 位 VNNI）上各自
启用最优后端，全部 bit-exact。本轮把 2026-08-31 之后的 R1（浮点归约 kBitExact）、
R2（dot4_packed 4 链）、R3（mkern/gemm 微内核）**在真 AVX-512 硬件上补验**。

## 1. 背景

SGN SIMD 原语层含 AVX-512 服务器加速内核（P1）。此前 Arrow Lake（无 AVX-512）只能
逻辑验证 AVX-512 指令，本轮在远程 EPYC（Zen 4，全核 AVX-512）独立验证
`mkern/simd/` + `mkern/gemm/`：**正确性 + 性能基准**。

## 2. 测试环境

| 项目 | 详情 |
|---|---|
| CPU | AMD EPYC 9Y24 96-Core（Zen 4，family 25 model 17），KVM 完全虚拟化 |
| 分配 vCPU | 2 核（无超线程） |
| 频率 | ~2.6 GHz（rdtsc 实测口径） |
| 内存 | 3.9 GiB（虚拟机） |
| OS | Debian Linux（内核 6.6.95-bck.2） |
| 编译器 | g++ 11.4.0（Ubuntu 22.04），C++23 |
| 编译选项 | `-O3 -ffp-contract=off`（浮点归约禁 FMA 收缩保 kBitExact；CMake / build_remote.sh 双路径） |
| 运行时后端 | **`avx512vnni`**（CPUID 自动检测：`avx2=1, avx_vnni(sub1.EAX[4])=0, avx512vnni=1 → expect=avx512vnni`） |

CPU 关键指令集：AVX2, AVX-512F/DQ/CD/BW/VL/IFMA/VBMI/VBMI2/**VNNI**/BITALG/
VPOPCNTDQ/BF16, GFNI, VAES, VPCLMULQDQ, SHA-NI, BMI1/2。
> 注：Zen 4 无 256 位 AVX-VNNI（VEX），运行时经 CPUID 正确选中 512 位 VNNI（EVEX），
> 不触发 256 位路径。AVX-VNNI 位定义勘误见 Arrow Lake 归档 §2（sub1 EAX[4]）。

## 3. 测试方法

与 Zen 5 / Arrow Lake 归档一致（同一测试逻辑）：预热、`volatile sink`、us/call + Mops/s、
K∈{1024,4096,16384,65536}；**正确性先于性能**（`simd_boundary_test` / `gemm_boundary_test`
ALL PASSED 后再采）。

## 4. 正确性（层全绿）

- **simd 原语层**：238/238（dot16 18、dot8/dot4 28、sum_f32 系 108、decode 10、reverse/batch 64、accum 10）
- **gemm 微内核层**：**4819/4819**（三方对拍：dispatch vs 标量锚点 vs 朴素参照，含越界/尾部/满幅/K=0/K=65536/accum 双态）

## 5. 性能基准（后端 `avx512vnni`）

### 5.1 原语层（K=65536；dot4_packed 为 R2 新增）

| 原语 | us/call | Mops/s | 备注 |
|---|---|---|---|
| dot16（512 位 madd） | 2.944 | 22,257 | madd 快速路径 + vpmuldq 回退 |
| dot8（512 位 VNNI） | 1.166 | 56,228 | vpdpbusd 512 位 |
| dot4 | 1.163 | 56,364 | 预解包输入（同 dot8 载体） |
| **dot4_packed** | 0.737 | **88,868** | **R2 打包路径，反超解包 1.58×**（4 位带宽红利兑现，比 Arrow Lake 1.30× 更强） |
| sum_f32 | 6.725 | 9,745 | **R1 固定 8 路树，kBitExact** |
| decode_i16_f32 | 11.055 | 5,928 | 带宽型 |

### 5.2 GEMM 微内核层（后端 avx512vnni）

| 规模 | gemm_i8 tiled | gemm_i8 naive(dot8) | gemm_i16 tiled | gemm_i16 naive(dot16) | f32 ref 朴素 |
|---|---|---|---|---|---|
| 64×64×576 | 0.43 | 0.35 | 0.12 | 0.10 | 0.01 |
| 256×256×576 | 2.44 | 1.71 | 0.76 | 0.70 | 0.04 |
| 1024×1024×4096 | **37.98** (≈46% AVX512-VNNI 峰值) | 30.07 | 6.97 | 10.93 | 0.61 |

（GMAC/s）

### 5.3 要点与兼容解读

1. **dot4_packed 反超解包 1.58×**（88.9k vs 56.4k）——R2 4 位打包在服务器带宽受限场景
   收益比桌面更强，周验证了"0.6× 是次优实现所致、带宽红利在出 L1 兑现"的修订判断。
2. **gemm_i8 大矩阵 37.98 GMAC/s = 29.3 MACs/cycle ≈ 46% AVX512-VNNI 理论峰值**；
   tiled/naive 仅 1.26×（数据复用收益 4 行 tile 尚待加宽，约 2× 优化空间=后续项）。
3. **gemm_i16 大形状 tiled 反比 naive 慢（0.64×）**——已标注已知项：AVX2 上无字节
   VNNI 等价物，真正加速在 AVX512-VNNI `vpdpwssd`（Zen 5/IPC 后续项）。
4. **兼容性证据**：同一套源码 + 同一 bit-exact 结果，在 Zen 4 走 512 位 VNNI、
   在 Arrow Lake 走 256 位 VNNI——吞吐差异反映指令宽度/频率/虚拟机资源，非代码差异。

## 6. 结论与后续

- **结论**：mkern 层在真 AVX-512 硬件上正确性全过（simd 238/238 + gemm 4819/4819），
  R1 归约 kBitExact、R2 dot4_packed 真机确认；性能符合设计预期。
- **后续**：① 远程 Zen 5 / 本机 Arrow Lake 已补齐（见各自归档）；② gemm_i8 提
  roofline（加宽 tile / A 广播 / K unroll）；③ gemm_i16 大形状 B 面板预打包 +
  vpdpwssd 内核；④ 多核 OpenMP（narrow_dot 层并行）属 P2。
